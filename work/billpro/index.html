01 — Context

More than an invoice generator.

A small business doesn’t have a “billing problem” in isolation. Every invoice touches stock, a customer balance, tax calculations and a record someone will need to find later. BillPro brings those connected tasks into one MERN application.

I built it around business-level data separation: users belong to a business, and backend operations use that business context. Invoices, products, purchases, quotations, customers, employees and reports share the same foundation rather than becoming disconnected tools.

The aim is straightforward: keep the workflow understandable, and make the server responsible for the numbers that matter.

02 — Architecture

Clear boundaries. Shared logic.

The React client talks to an Express API. Middleware handles security, authentication and permissions before a controller reaches the business logic. Mongoose models describe the data; PDFKit turns stored transactions into documents.

The important choice is what the frontend does not own: final tax totals, stock validation and customer balance updates. Those belong behind the API.

03 — The GST decision

Calculate once. Use it everywhere.

Invoices, purchases and quotations should not disagree about tax. The shared backend/utils/billing.js helper calculates each line’s taxable amount, applies the interstate or intrastate split and combines totals with rounding.

For example, on a taxable value of ₹1,000 at 18% GST:

Transaction Tax treatment Total
Intrastate ₹90 CGST + ₹90 SGST ₹1,180
Interstate ₹180 IGST ₹1,180
Zero-rated line No GST added at 0% ₹1,000

Discounts are applied before tax and clamped so they cannot make a line’s taxable amount negative. The helper accepts an explicit interstate flag; the controller supplies the transaction context.

04 — Data model

Keep a record of the movement.

An invoice captures the line-item values at the time of sale. A stock movement separately records how a product’s quantity changed, with a reference back to the transaction. These are abbreviated shapes from the models, not the complete schema.

Invoice item {
  product, name, sku, hsnCode, unit,
  quantity, unitPrice,
  discount, discountType,
  taxableAmount, taxRate,
  cgstAmount, sgstAmount, igstAmount, total
}

StockMovement {
  businessId, productId,
  type,              // SALE, PURCHASE, RETURN, ADJUSTMENT
  quantity,          // positive in; negative out
  previousStock, newStock,
  referenceId, referenceNumber,
  note, performedBy, timestamps
}
05 — Testing

Test the maths, not just the route.

The repository contains Jest tests for the billing helpers and Supertest API tests. The calculation suite calls the same functions used by the controllers, independently of an HTTP server or a database.

  • CGST and SGST split evenly for intrastate transactions.
  • Interstate transactions use IGST instead.
  • Discounts, quantities, zero tax and totals receive dedicated checks.
  • API tests use an in-memory MongoDB setup.

06 — Performance & trade-offs

Start with the boring improvements.

Indexed MongoDB queries, pagination, compression and database-level aggregation keep reporting and list endpoints from doing unnecessary work. These are implementation choices, not a substitute for measuring real workloads.

What I would change next

Before a production rollout, I would audit the development/demo authentication paths, verify transactional consistency when invoice and inventory updates fail midway, and measure representative datasets. The next priority is a safely seeded public demo with a repeatable reset process—not more dashboard widgets.

BillPro’s source is public. A verified public demo URL and demo account have not yet been supplied, so this portfolio does not publish invented credentials.
